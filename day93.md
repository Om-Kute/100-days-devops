🚀 Day 93/100 – Logging & Centralized Log Management
📝 Collect • Store • Search • Visualize • Troubleshoot

Day 93 focuses on Logging and Centralized Log Management, an important part of modern DevOps, observability, security, and production troubleshooting.

Applications and infrastructure generate large amounts of logs every day. Instead of checking logs individually on every server or container, centralized logging collects them into a common platform where engineers can search, filter, analyze, visualize, and troubleshoot system behavior.
🔍 1. What is Logging?

Logging is the process of recording events generated by applications, operating systems, containers, databases, and infrastructure.

A log can contain information such as:

Timestamp
Log Level
Service
Message
Request ID
User ID
IP Address
HTTP Method
URL
Status Code
Response Time

Example:

{
  "timestamp": "2026-09-27T10:15:30Z",
  "level": "ERROR",
  "service": "payment-service",
  "message": "Payment processing failed",
  "request_id": "a1b2c3d4",
  "status_code": 500,
  "response_time": "2.3s"
}

🗂️ 3. Types of Logs
🐧 System Logs

Generated by operating systems.

Examples:

Authentication logs
Kernel logs
Service logs
System events
SSH logs

On Linux, common locations include:

/var/log/

Useful command:

ls /var/log/
🌐 Web Server Logs

Web servers such as Nginx and Apache generate:

Access Logs
Error Logs

Example:

192.168.1.10 - - [27/Sep/2026:10:20:10 +0000]
"GET /index.html HTTP/1.1" 200 1024
💻 Application Logs

Applications can generate:

INFO
DEBUG
WARN
ERROR
FATAL

Example:

INFO Application started
WARN Database response slow
ERROR Database connection failed
🐳 Container Logs

Docker containers generate application output that can be viewed using:

docker logs <container-name>

Example:

docker logs nginx

Follow logs:

docker logs -f nginx
☸️ Kubernetes Logs

View Pod logs:

kubectl logs <pod-name>

Follow logs:

kubectl logs -f <pod-name>

View logs from a specific container:

kubectl logs <pod-name> -c <container-name>

View logs from previous container instance:

kubectl logs <pod-name> --previous
🏗️ 4. What is Centralized Logging?

In a traditional environment:

Server 1 → Logs
Server 2 → Logs
Server 3 → Logs
Server 4 → Logs

An engineer has to connect to each server separately.

With centralized logging:

Server 1 ──┐
Server 2 ──┤
Server 3 ──┼──> Log Collector
Server 4 ──┤
Containers ─┘        │
                     ▼
              Centralized Storage
                     │
                     ▼
                Search & Analysis
                     │
                     ▼
                Visualization

This makes troubleshooting much easier.

Full-text search
Filtering

Distributed storage
Fast querying

Example architecture:

Logs
 ↓
Elasticsearch
 ↓

 ↓
Kibana
⚙️ 9. Logstash

Logstash is a data processing pipeline that can collect, transform, and send logs to destinations.

Conceptually:

Input
  ↓
Filter
  ↓
Output

Example:

Log File
   ↓
Logstash
   ↓
Parse JSON
   ↓
Add Fields
   ↓
Elasticsearch

A simplified Logstash pipeline:

input {
  file {
    path => "/var/log/app.log"
  }
}

filter {
  json {
    source => "message"
  }
}

output {
  stdout {
    codec => rubydebug
  }
}
