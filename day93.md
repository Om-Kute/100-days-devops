🚀 Day 93/100 – Logging & Centralized Log Management
📝 Collect • Store • Search • Visualize • Troubleshoot

Day 93 focuses on Logging and Centralized Log Management, an important part of modern DevOps, observability, security, and production troubleshooting.

Applications and infrastructure generate large amounts of logs every day. Instead of checking logs individually on every server or container, centralized logging collects them into a common platform where engineers can search, filter, analyze, visualize, and troubleshoot system behavior.
🔍 1. What is Logging?

Logging is the process of recording events generated by applications, operating systems, containers, databases, and infrastructure.

A log can contain information such as:

Timestamp
Log Level
Service
Message
Request ID
User ID
IP Address
HTTP Method
URL
Status Code
Response Time

Example:

{
  "timestamp": "2026-09-27T10:15:30Z",
  "level": "ERROR",
  "service": "payment-service",
  "message": "Payment processing failed",
  "request_id": "a1b2c3d4",
  "status_code": 500,
  "response_time": "2.3s"
}

🏗️ 4. What is Centralized Logging?

In a traditional environment:

Server 1 → Logs
Server 2 → Logs
Server 3 → Logs
Server 4 → Logs

An engineer has to connect to each server separately.

With centralized logging:

Server 1 ──┐
Server 2 ──┤
Server 3 ──┼──> Log Collector
Server 4 ──┤
Containers ─┘        │
                     ▼
              Centralized Storage
                     │
                     ▼
                Search & Analysis
                     │
                     ▼
                Visualization

This makes troubleshooting much easier.

  ↓

  ↓

Example:

   ↓
Logstash

🧱 13. Loki

Grafana Loki is a log aggregation system designed to work well with Grafana.

A key design characteristic is that Loki does not index the full content of every log line in the same way Elasticsearch does. Instead, it primarily indexes labels and stores the log content separately.

This can make it attractive for teams already using Grafana and Prometheus.

📊 22. Grafana Log Exploration

With Loki configured as a Grafana data source, logs can be explored using LogQL.

Example:

{app="payment-service"}

Filter for errors:

{app="payment-service"} |= "ERROR"

Filter by JSON fields:

{app="payment-service"} | json | level="error"

Search for timeout messages:

{app="payment-service"} |= "timeout"

The exact labels and parsed fields depend on the collector and Loki configuration.

🔎 23. Useful Log Queries

Examples of useful searches:

level="ERROR"
service="payment-service"
status_code=500
message contains "timeout"

For Kubernetes:

namespace="default"

For a specific container:

container="api"

The exact syntax depends on the logging platform being used.
