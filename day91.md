🚀 Day 91/100 – Monitoring & Observability
📊 Monitor • Visualize • Alert • Troubleshoot

Day 91 begins the final phase of my 100 Days of DevOps journey with Monitoring & Observability.

In modern DevOps environments, deploying applications is only part of the job. We also need to understand:

Is the application healthy?
Is CPU usage increasing?
Is memory running out?
Are containers failing?
Is the application responding correctly?
Are users experiencing errors?
When did the problem start?
What caused the problem?

Monitoring and observability provide the visibility required to answer these questions.
🔍 1. What is Monitoring?

Monitoring is the process of continuously collecting and analyzing system information to determine whether infrastructure and applications are operating normally.

Examples of monitored metrics:

CPU Usage
Memory Usage
Disk Usage
Network Traffic
Request Count
Response Time
Error Rate
Container Count
Pod Status
Application Availability

A simple monitoring workflow:

System
   ↓
Metrics
   ↓
Monitoring Tool
   ↓
Dashboard
   ↓
Alert
   ↓
Engineer
🔭 2. What is Observability?

Observability is the ability to understand the internal state and behavior of a system from the information it produces.

The three commonly discussed pillars are:

             Observability
                  │
        ┌─────────┼─────────┐
        │         │         │
        ▼         ▼         ▼
      Metrics    Logs     Traces
Metrics

Numerical measurements over time.

Examples:

CPU = 72%
Memory = 68%
Requests = 1,250/sec
Error Rate = 0.5%
Logs

Records of events generated by applications and infrastructure.

Example:

2026-09-25 10:20:31 ERROR Database connection failed
Traces

Track a request as it travels through multiple services.

User
 ↓
API Gateway
 ↓
Service A
 ↓
Service B
 ↓
Database

Traces are especially useful in distributed systems and microservices.
🆚 3. Monitoring vs Observability
Monitoring	Observability
Detects known problems	Helps investigate unknown problems
Focuses heavily on metrics	Uses metrics, logs and traces
Answers "Is something wrong?"	Helps answer "Why is it wrong?"
Dashboards and alerts	Deeper system understanding
Often threshold-driven	Supports exploratory troubleshooting

Both are important for reliable DevOps systems.

🔥 5. Prometheus

Prometheus is an open-source monitoring and alerting toolkit.

It is widely used for collecting and querying time-series metrics.

Prometheus can:

Scrape metrics
Store time-series data
Query metrics using PromQL
Evaluate alerting rules
Integrate with Alertmanager
Monitor infrastructure and applications
📡 6. Prometheus Pull Model

⚙️ 11. Prometheus Configuration

A simplified prometheus.yml:

global:
  scrape_interval: 15s

scrape_configs:

  - job_name: "prometheus"
    static_configs:
      - targets:
          - "localhost:9090"

  - job_name: "node-exporter"
    static_configs:
      - targets:
          - "localhost:9100"
Explanation
scrape_interval
       ↓
How frequently Prometheus collects metrics

job_name
       ↓
Identifies the monitoring target

targets
       ↓
Endpoints Prometheus should scrape
🧮 12. PromQL

Prometheus uses PromQL (Prometheus Query Language) to query metrics.

Example:

up

Shows whether targets are available.

CPU-related example:

node_cpu_seconds_total

Memory example:

node_memory_MemAvailable_bytes

HTTP request example:

http_requests_total

PromQL can also perform calculations, filtering, aggregation, and rate calculations.

Example:

rate(http_requests_total[5m])

This calculates the per-second rate of increase over the selected five-minute range.
